# 토마토 키오스크 UI 데모

Figma의 `04-2_상태 및 팝업_휴대폰 회원 [1080×1920]` 페이지 중 `01_Start / 상품 미등록`과 내부 `04_Payment`를 기준으로 만든 GitHub Pages용 정적 데모입니다. 빌드나 패키지 설치 없이 `index.html`을 바로 열어 사용할 수 있습니다.

## 파일 구성

- `index.html`: 1080×1920 키오스크 화면과 접근성 구조
- `styles.css`: 화면·모달·모션 스타일. 속성 하나당 한 줄로 정리됨
- `app.js`: 상품, 바코드, 장바구니, 회원, 포인트 내역, 결제 시연 로직
- `assets/`: Figma에서 추출한 결제 삽화와 상태 아이콘

## 초기 화면 기준

- 장바구니가 비어 있으면 결제수단과 `결제하기` 버튼이 비활성화됩니다.
- 상품을 담으면 상품 행 바로 아래에 `결제 요약`이 생성되며, 수량 변경·삭제 때 위치와 금액이 즉시 다시 계산됩니다.
- 행사 상품은 원가, 행사 할인액, 할인 적용 금액이 장바구니와 결제 요약에 함께 표시됩니다.
- 결제 영역은 Figma와 동일하게 상단 안내·봉투 구매·전체 취소·결제하기, 하단 결제금액·결제수단 구조로 배치했습니다.
- 상품 선택 카드는 별도 이미지 없이 상품명·가격·행사 표시만 사용합니다.
- 회원 정보는 초기 화면에 나오지 않으며, 회원 확인 또는 가입 이후 헤더 오른쪽에 휴대폰 번호와 보유 포인트가 두 줄로 표시됩니다.

## 빠른 시연 순서

1. 오른쪽 `상품 직접 선택`에서 상품을 눌러 장바구니에 담습니다.
2. 화살표나 좌우 스와이프로 8개 카테고리를 이동합니다.
3. 결제수단을 선택하고 `결제하기`를 누르면 `03 포인트 확인` 화면이 열립니다.
4. `휴대폰 번호로 확인` 또는 `신규 회원가입`을 누르면 `03-A 휴대폰 번호 확인` 화면으로 이동합니다.
5. 휴대폰 번호의 `010`은 실제 입력값으로 자동 완성되며, 나머지 8자리만 입력합니다. 테스트 회원 `010-1234-1234`를 입력하면 `04 보유 포인트 조회·사용` 화면에서 `4,259P`를 확인할 수 있습니다.
6. `직접 입력`은 `04-A` 화면을 열며, 50P 단위가 아니면 `E1` 오류 상태가 표시됩니다.
7. 등록되지 않은 번호는 `03-B 회원 미가입 안내`로 이동합니다. 가입 시 `5,000P` 지급 완료 화면을 3초간 보여준 뒤 선택한 결제수단으로 진행합니다.
8. 신용카드·현금은 3초 뒤 결제 완료, 간편결제는 3초 뒤 승인 오류로 이동합니다.
9. 승인 오류의 `결제수단 변경`에서 카드·간편·현금 중 하나를 다시 고를 수 있습니다.

## 회원 DB

- Chrome에서는 IndexedDB의 `tomato-kiosk-demo / members` 저장소를 사용합니다.
- IndexedDB를 쓸 수 없는 환경에서는 localStorage로 자동 대체합니다.
- 신규 가입 시 해당 브라우저에 회원 번호와 `5,000P`가 저장됩니다.
- 결제에 사용한 포인트는 성공 시 차감되어 새로고침 후에도 유지됩니다.
- 테스트 회원은 `010-1234-1234 / 4,259P`로 자동 생성됩니다.
- 장바구니는 저장하지 않으므로 페이지를 새로 열거나 새로고침하면 항상 빈 상태입니다.

## 바코드 스캐너와 포인트 내역

- 상품 스캔 화면에서는 보이지 않는 전용 입력창에 포커스가 유지됩니다. 모달이 열리면 모달 조작을 위해 자동 포커스를 잠시 중단합니다.
- `8809219929858`은 `서리태 가득 콩물두유`(시연가 2,500원), `8801223100209`는 `초정 탄산수`(시연가 1,500원)로 장바구니에 추가됩니다.
- 등록되지 않은 코드는 관리자 문의 모달을 표시하며, `확인`을 누르거나 3초가 지나면 닫힙니다.
- 상단 `포인트 조회`에서 회원을 확인하면 회원 번호와 보유 포인트가 두 줄로 표시되고 `내역 조회`가 활성화됩니다.
- 포인트 내역은 ERP 연동 예정 컬럼인 `일시`, `적립/사용구분`, `적립`, `사용`을 그대로 사용하며 최근 1주일·1개월·3개월 필터를 제공합니다.

## 화면 크기

기준 디자인은 `1080×1920`입니다. 너비는 1080px을 기준으로 유지하고, 브라우저 높이가 1600~1920px이면 세로 영역만 해당 높이에 맞춰 유연하게 조절합니다. 브라우저 높이가 1600px 미만이면 다시 1920px 화면으로 고정하여 세로 스크롤로 확인합니다. 1920px보다 높은 브라우저에서도 최대 높이는 1920px입니다. 브라우저 폭이 1080px보다 좁을 때만 전체 화면을 가로 폭에 맞춰 비율 축소합니다.

## 삽화 자산

빈 장바구니, 카테고리 화살표, 결제수단, 카드 리더기, 바코드 스캔, 현금 투입구, 결제 완료·오류 아이콘은 Figma 벡터 노드를 투명 PNG로 렌더링해 로컬 `assets/`에 포함했습니다. 외부 Figma URL을 사용하지 않아 링크 만료나 CORS 문제 없이 GitHub Pages에서 표시됩니다. 카드 리더기는 원본 프레임의 눌려 보이는 세로 비율을 코드에서 보정했습니다. 실제 서비스로 전환할 때는 같은 노드를 SVG로 export하고 현재 `<img>` 경로만 교체하면 됩니다.

## GitHub Pages 배포

ZIP의 내용물을 저장소 루트에 덮어쓴 뒤 커밋하고 푸시합니다.

```bash
git add index.html styles.css app.js assets README.md
git commit -m "Rebuild kiosk demo flow"
git push origin main
```

GitHub Pages가 이미 `main` 브랜치에서 배포되도록 설정되어 있다면 별도 배포 명령은 필요 없습니다. 푸시 후 Pages 빌드가 자동으로 다시 실행되며, 보통 잠시 뒤 기존 URL에 반영됩니다. 브라우저 캐시가 남으면 강력 새로고침을 사용하세요.

`index.html`의 CSS·JavaScript 경로에는 배포 버전 쿼리가 포함되어 있습니다. 새 수정본을 배포할 때 이 버전값을 변경하면 GitHub Pages나 브라우저가 이전 파일을 재사용하는 문제를 방지할 수 있습니다.

## 시연용 추가 편의 기능

- 상품 추가·모달 열림·진행 상태에 짧은 전환 애니메이션 적용
- 물리 키보드 숫자·Backspace·Enter 지원
- 물리 바코드 스캐너의 연속 숫자 입력과 Enter 종료 입력 지원
- 결제 완료 후 8초 자동 초기화와 영수증 선택
- 간편결제 오류 후에도 장바구니·회원·포인트 상태 보존
- 접근성 포커스 표시와 `prefers-reduced-motion` 대응
- 주요 화면 구조는 CSS Grid와 Flexbox로 구성
